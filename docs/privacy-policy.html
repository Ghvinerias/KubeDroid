KubeDroid

Privacy Policy

Last updated: March 2026  ·  Effective immediately

TL;DR — The short version
  • KubeDroid collects no personal data whatsoever
  • All credentials stay on your device, encrypted
  • The app only contacts your own Kubernetes clusters
  • No analytics, no tracking, no ads, no third-party SDKs
  • We have no servers — there is nothing to share or sell

1. Overview

KubeDroid is a native Android application for managing Kubernetes clusters. This policy describes how the app handles your data.

The short answer: it doesn't. KubeDroid is designed as a purely local tool. It connects directly from your device to your Kubernetes clusters. There are no KubeDroid servers, no accounts, no telemetry, and no data collection of any kind.

2. Data We Do Not Collect

KubeDroid does not collect, transmit, or store any of the following:

  • Personal information (name, email, phone number)
  • Device identifiers (IMEI, Android ID, advertising ID)
  • Location data
  • Usage analytics or crash reports
  • App usage patterns or behaviour tracking
  • Kubernetes cluster contents, workloads, or configurations
  • Log output from your pods
  • Any data entered or viewed in the app

3. Credentials & Secrets

KubeDroid stores cluster connection credentials (kubeconfig files, cloud provider credentials, auth tokens) exclusively on your device using the Android Keystore system and EncryptedSharedPreferences.

  • Credentials are encrypted at rest using AES-256-GCM
  • Credentials are never transmitted to any server other than your own clusters
  • Access tokens are never written to disk — held in memory only for the duration of use
  • Kubernetes Secret values require biometric authentication to view
  • Revealed secret values auto-hide after 30 seconds
  • Credentials are excluded from Android cloud backups and device transfers

Deleting the app permanently removes all stored credentials from your device. There is no account to delete and no server-side data to request removal of.

4. Network Connections

KubeDroid makes network connections only to:

  • Your Kubernetes clusters — the API server endpoints you configure in the app
  • Cloud provider auth endpoints (if using GCP/AWS/Azure) — solely to obtain access tokens for your own clusters:
    • GCP: accounts.google.com, oauth2.googleapis.com, container.googleapis.com
    • AWS: sts.amazonaws.com, eks.{region}.amazonaws.com
    • Azure: login.microsoftonline.com, management.azure.com
  • Google Fonts CDN — to load the JetBrains Mono typeface on first use

No connection is ever made to any KubeDroid-operated server. We do not have any servers.

5. Third-Party SDKs & Libraries

KubeDroid does not include any advertising SDKs, analytics SDKs, or social login SDKs that collect user data.

Libraries used and their data handling:

  • kubernetes-client/java — Kubernetes API client. Makes requests to your cluster only.
  • OkHttp — HTTP client. No telemetry.
  • Jetpack Compose — Android UI framework by Google. No data collection.
  • Android Biometric — Biometric authentication. Credentials never leave the device.
  • Google Fonts — Font loading. Google's standard font API privacy policy applies to this request.

6. Permissions

KubeDroid requests the following Android permissions:

  • INTERNET — Required to connect to your Kubernetes API servers.
  • USE_BIOMETRIC / USE_FINGERPRINT — Required for biometric app lock and secret reveal. Authentication is performed entirely on-device by Android. KubeDroid never receives or stores biometric data.

No other permissions are requested.

7. Children's Privacy

KubeDroid is a developer tool intended for adults managing Kubernetes infrastructure. It is not directed at children under 13. We do not knowingly collect any information from children.

8. Changes to This Policy

If this policy changes materially, the updated version will be posted at this URL with a revised effective date. Given the nature of the app (no data collection), material changes are unlikely.
